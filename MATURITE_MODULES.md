# Maturité des modules — 3 octobre 2026

> Actualisation de mise en œuvre du 6 octobre : [suivi courant](SUIVI_RECOMMANDATIONS.md).
> Le paiement documentaire, les services activables et la navigation ont de nouvelles
> recettes ; la publication et les intégrations réelles restent à qualifier.

Cette classification porte sur le code et les recettes locales documentées dans [le suivi](SUIVI_RECOMMANDATIONS.md). Elle ne certifie pas que tout le worktree est déployé sur le domaine public. Le processus API de production a été rechargé pour activer la protection Swagger, mais les neuf migrations en attente ne sont pas appliquées ; les comptes de démonstration doivent être remplacés avant l’activation du refus des mots de passe seed. Les compilations frontend de recette sont isolées hors du répertoire servi par Nginx.

« Opérationnel en recette » indique un cycle métier exécuté par HTTP avec ses refus et ses états persistés. « Pilote » indique une interface et des API présentes dont les écritures complètes, l’intégration externe ou la validation métier restent à qualifier. « Restant à livrer » désigne les travaux identifiés pour terminer la qualification. Aucune ligne n’annonce une intégration externe comme opérationnelle sur la seule base d’un test simulé.
